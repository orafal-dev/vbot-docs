title: Module Scheduling
description: Timers, repeating tasks, and script lifecycle with Module
---

The `Module` library provides scheduling helpers built on `Module.New`, `Stop`, `Pause`, and `Resume`. Use it for any repeating or delayed script logic instead of manual loops.

## Primary API

| Function | Description |
| --- | --- |
| `Module.Every(name, callback, delayMs)` | Run callback on a fixed interval (recommended) |
| `Module.After(name, callback, delayMs)` | Run callback once after a delay |
| `Module.New(name, callback, delayMs)` | Create a custom recurring module |
| `Module.Stop(name)` | Stop and remove a module |
| `Module.Pause(name)` / `Module.Resume(name)` | Pause/resume execution |
| `Module.Cancel(name)` | Cancel a pending one-shot (`Every`/`After` registry) |
| `Module.Exists(name)` | Check if a managed module is registered |
| `Module.Get(name)` | Get module metadata |
| `Module.List()` | List managed modules |
| `Module.PauseManaged(name)` / `Module.ResumeManaged(name)` | Managed pause/resume variants |

`Module.Every` stops an existing module with the same name before registering the new one and records it in the core helper registry. `Module.After` waits, invokes once, then removes itself. `Cancel`, `PauseManaged`, `ResumeManaged`, `Exists`, `Get`, and `List` operate on modules created through `Every` or `After`; raw `Module.New` modules are not added to that Lua-side registry.

Names must be non-empty and script-specific. Delays are integer milliseconds from 0 through 86,400,000. Callbacks may call `wait(...)`; they must not busy-loop.

## Error policy

An uncaught callback error is reported with script/module context and stops the offending module. It stops the entire script only when no healthy sibling work remains. Do **not** wrap the whole repeating callback in `pcall`; catch only an operation whose failure is expected and recoverable.

## Example: repeating health check

```lua
local SCRIPT_ID = "low_hp_sound"

local function tick()
    if not Self.IsAvailable() then
        return
    end

    local hp = Self.GetHealthPercentage()
    if type(hp) == "number" and hp <= 35 then
        Sound.PlayByIdSmart(BotSoundId.LOW_HEALTH)
    end
end

function init()
    Module.Every(SCRIPT_ID .. "_tick", tick, 1000)
end
```

## Example: delayed one-shot

```lua
Module.After("delayed_greet", function()
    if Self.IsAvailable() then
        Self.Say("Ready!")
    end
end, 5000)
```

For owner-scoped one-shots that need cancelable IDs, prefer `Events.Schedule` — see [Events & HUD](/docs/guides/events-hud).

## Naming modules

Use unique, descriptive module names — typically prefixed with your script ID to avoid collisions:

```lua
Module.Every("my_script_scan", callback, 500)
Module.Every("my_script_hud", callback, 1000)
```

## Lifecycle

Prefer starting modules from `init()`. Native owner-scoped modules are cleaned when the script stops; explicit `Module.Stop` is still useful when reloading mid-session:

```lua
Module.Stop(SCRIPT_ID .. "_tick")
```

See the full function list in [Module API Reference](/docs/api-reference/module).
