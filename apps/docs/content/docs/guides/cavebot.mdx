`Cavebot` orchestrates the Walker and Lure Manager features. It is the primary module for route automation, waypoint scripts, and supply actions.

## Top-level control

| Function | Description |
| --- | --- |
| `Cavebot.SetEnabled(enabled)` | Enable/disable cavebot |
| `Cavebot.Enable()` / `Disable()` | Shortcuts |
| `Cavebot.IsEnabled()` | Status check |
| `Cavebot.SetLureEnabled(enabled)` | Enable/disable lure |
| `Cavebot.EnableLure()` / `DisableLure()` | Lure shortcuts |
| `Cavebot.IsLureEnabled()` | Lure status |
| `Cavebot.SetEnginesEnabled(walker, lure)` | Both at once |
| `Cavebot.Resume()` | Resume walker |
| `Cavebot.Defer(timeoutMs)` | Owner-scoped hold inside an interceptor |
| `Cavebot.GoTo(labelName)` / `GoToLabel(labelName)` | Jump to label |
| `Cavebot.Pause(ms, autoResume)` | Temporary pause |
| `Cavebot.Save(path, features?)` | Save `.validuswpt` bundle |
| `Cavebot.Load(path, features?)` | Queue `.validuswpt` load |
| `Cavebot.GetStatus()` / `PrintStatus()` | Debug status |

### Profile waypoint bundles

`Cavebot.Save` / `Load` write and queue `.validuswpt` bundles. Each returns `true, resolvedPath`; path or queue errors raise a Lua error. Walker and Lure are always included. The optional `features` table selects Targeting, Magic Shooter, and/or Looter via `Cavebot.BundleFeature.*`; `nil` selects none of those optional sections.

A bare filename is searched beside the running script, then in the product `Waypoints` folder. Loads are queued until Lua dispatch unwinds and may stop running waypoint scripts.

```lua
Cavebot.Load("hunt.validuswpt", {
    Cavebot.BundleFeature.Targeting,
    Cavebot.BundleFeature.Looter,
})
```

## Events

Prefer explicit observe / intercept / lifecycle APIs. Legacy `OnLabel` and `OnAction` retain historical blocking behavior.

### Non-blocking observers

| Function | Behavior |
| --- | --- |
| `Cavebot.ObserveLabel(callback)` | Label reached; cannot pause Walker |
| `Cavebot.ObserveAction(callback)` | Action waypoint reached (before interceptors finish) — not a success signal |
| `Cavebot.ObserveWaypointChange(callback)` | Selected waypoint changed |
| `Cavebot.OnWaypointChange(callback)` | Compatibility alias for `ObserveWaypointChange` |
| `Cavebot.OnActionStarted(callback)` | Action actually started |
| `Cavebot.OnActionCompleted(callback)` | Terminal Action result |

`ObserveWaypointChange` receives one table with `previousIndex`, `index`, `type`, `x`, `y`, `z`, `label`, `labelName`, and `uniqueId`. Indices are 1-based; `previousIndex` is `nil` for the initial selection.

`OnActionStarted` / `OnActionCompleted` each receive one table with `executionId`, `action`/`name`, numeric `kind`, and a `waypoint` table (`index`, `uniqueId`, `x`, `y`, `z`). Completion additionally includes:

| Field | Meaning |
| --- | --- |
| `ok` | `true` only on successful terminal result |
| `outcome` | `success`, `skipped`, `failure`, `timeout`, or `cancelled` |
| `description` | Result or error description |
| `result` / `error` | Description on success / failure; otherwise `nil` |
| `durationMs` | Elapsed ms from actual Action start |

Use `executionId` to correlate start with exactly one completion. Changing the selected waypoint, replacing/deleting the Action, clearing/reloading the route, or resetting Walker completes an active Action as `cancelled`.

### Blocking interceptors

| Function | Behavior |
| --- | --- |
| `Cavebot.InterceptLabel(callback)` | Preferred blocking label interceptor |
| `Cavebot.InterceptAction(callback)` | Preferred blocking Action interceptor |
| `Cavebot.OnLabel(callback)` | Legacy blocking alias |
| `Cavebot.OnAction(callback)` | Legacy blocking alias |

Blocking interceptors release automatically when their callback returns. Call `Cavebot.Defer(timeoutMs)` only inside an interceptor when work must continue after return. It returns an owner-scoped handle with `handle:Complete()` and `handle:Cancel()`; both release the hold and return `true` only on the first successful release. `timeoutMs` must be between 1 and 60000; expiration fails open.

```lua
Cavebot.ObserveLabel(function(labelName)
    print("Reached label: " .. tostring(labelName))
end)

Cavebot.OnActionCompleted(function(event)
    print(event.outcome, event.description, event.durationMs)
end)

Cavebot.RegisterEvent(eventId, callback)
Cavebot.UnregisterAllEvents()
```

## Walker

Full waypoint and walker control:

| Category | Key functions |
| --- | --- |
| Control | `SetEnabled`, `IsEnabled`, `Resume`, `Defer`, `CompleteDeferred`, `GoTo`, `IsPausedByLua`, `SetPausedByLua` |
| Waypoints | `GetWaypoints`, `AddWaypoint`, `InsertWaypoint`, `ReplaceWaypoint`, `DeleteWaypoint`, `ClearWaypoints`, `SetWaypointPosition` |
| Special areas | `GetSpecialAreas`, `AddSpecialArea`, `UpdateSpecialArea`, `DeleteSpecialArea`, `ClearSpecialAreas`, `ReorderSpecialArea`, `IsPositionInsideSpecialArea` |
| Navigation mode | `SetNavigationMode`, `GetNavigationMode`, Auto Explore settings/status/connectors |
| Navigation | `GetSelectedWaypointIndex`, `SetSelectedWaypointIndex`, `SelectClosestWaypoint`, `GetWaypointCount` |
| Settings | `SetNodeDistance`, `SetStartFromNearestWaypoint`, `SetWalkToLureCenter`, `SetLeaveLureOnPlayer`, `SetLeaveLurePlayerMode` |
| Auto recorder | `SetAutoRecorderEnabled`, `GetAutoRecorderOptions`, `SetDistanceBetweenWaypoints` |
| Debug | `IsStuck`, `SetDebugHud`, `GetDebugHud` |

`Cavebot.Walker.Defer(timeoutMs)` / `CompleteDeferred(token)` implement the same owner-bound decision handshake as `Engine.Walker.Defer`.

### Special areas

Special Area records are detached snapshots with `index`, stable `id` / `uniqueId`, `x`, `y`, `z`, `width`, `height`, `featureMask`, and `enabled`. Adding requires `x`, `y`, and `z`; width and height default to 1 (range 1–10). Coordinates: `x`/`y` 1–65535, `z` 0–15. `featureMask` defaults to Walker (`1`) and `enabled` defaults to `true`.

Use `Cavebot.Walker.SpecialAreaFeature` (also on `Engine.Walker` and as global `SpecialAreaFeature`): Walker `1`, Targeting `2`, MagicShooter `4`, Looter `8`, All `15`. Masks may be combined. Update and delete use the stable ID, not the mutable row index; updates are partial. Geometry or scope mutations invalidate Walker's cached movement and refresh its HUD.

```lua
local id = Cavebot.Walker.AddSpecialArea({
    x = 32345,
    y = 32210,
    z = 7,
    width = 3,
    height = 3,
    featureMask = Cavebot.Walker.SpecialAreaFeature.Walker
        + Cavebot.Walker.SpecialAreaFeature.Targeting,
})
```

### Auto Explore

Navigation mode is `"waypoints"` or `"auto_explore"` (`Cavebot.Walker.NavigationMode.*`) and can change only while Walker is stopped. Styles are `"natural"`, `"thorough"`, and `"wide_roam"` (`AutoExploreStyle`). Settings updates are partial: `maximumFloorsUp` / `Down`, `allowWalkOn` / `Ladder` / `Rope` / `Hole` / `Teleport`, and `autoOpenDoors`.

Painted areas are edited only through World Map; scripts query containment with `IsAutoExplorePositionPainted`. Connectors use stable IDs, kinds `walk_on` / `ladder` / `rope` / `hole` / `teleport`, and explicit `source` / `destination` `{x,y,z}` positions. Pairing uses two reciprocal directed records — updating one mirrors only endpoints onto the reverse; deleting one leaves the reverse unpaired. Runtime status from `GetAutoExploreStatus()` is a detached snapshot (phase, positions, plannedPath, coverage, `latestFailureReason`, and related fields).

### Leave-lure player modes

| Mode | Value | Behavior |
| --- | --- | --- |
| `Cavebot.Walker.LeaveLurePlayerMode.NonAllyPlayers` | `0` (default) | Ignores party and guild/allied-guild players |
| `Cavebot.Walker.LeaveLurePlayerMode.AnyPlayer` | `1` | Reacts to every visible player other than the local character |

```lua
Cavebot.Walker.SetLeaveLureOnPlayer(true)
Cavebot.Walker.SetLeaveLurePlayerMode(Cavebot.Walker.LeaveLurePlayerMode.AnyPlayer)
```

### Waypoint script requirement

Script waypoints **must** call `Cavebot.Walker.Resume()` when done:

```lua
Self.Say("hi")
Cavebot.Walker.Resume()  -- required final line
```

If the script exits without resuming, the DLL auto-resumes with a warning. If the walker is disabled while a waypoint script runs, the script is stopped so the walker can be re-enabled.

### Position waypoint behavior

- **Weak Horizontal Stand** — tries exact tile, then X±1 on same Y/Z
- **Weak Vertical Stand** — tries exact tile, then Y±1 on same X/Z

## Actions

Built-in action types handled by `Cavebot.Actions.Run`:

`check_supplies`, `buy_supplies`, `sell_loot`, `open_depot`, `deposit_items`, `stash_items`, `withdraw_supplies`, `npc_say`, `bank`, `custom_script`, `tasker`, `imbuing`

### Action context conventions

| Field | Purpose |
| --- | --- |
| `actionType` / `action_type` | Selects the handler |
| `actionConfig` / `action_config` | Action-specific config |
| `successLabel` / `failureLabel` | Route walker after completion |

Handlers return a table with fields like `ok`, `actionType`, `error`, `pending`, `goToLabel`, and action-specific results.

### Custom action handler

```lua
Cavebot.Actions.Register("check_capacity_for_refill", function(context)
    local minCapacity = tonumber(context.minCapacity) or 100
    local capacity = Self.GetCapacity()

    if type(capacity) ~= "number" then
        return {
            ok = false,
            actionType = "check_capacity_for_refill",
            error = "capacity_unavailable",
            goToLabel = context.failureLabel,
        }
    end

    local needsRefill = capacity < minCapacity
    return {
        ok = true,
        actionType = "check_capacity_for_refill",
        needsRefill = needsRefill,
        goToLabel = needsRefill and context.failureLabel or context.successLabel,
    }
end)
```

## Lure Manager

The `Cavebot.Lure` namespace controls lure behavior:

| Category | Key functions |
| --- | --- |
| State | `GetState`, `IsLuring`, `IsFighting`, `GetLuredCreaturesCount` |
| Control | `SetEnabled`, `IsEnabled`, `SetForceLure`, `EndForceLure`, `SetOption` |
| Settings | `SetNearRange`, `SetAttackWhileLuring`, `SetConsiderOnlyReachable` |
| Slow walk | `SetSlowWalkDelayMs`, `SetSlowWalkingCreaturesCount`, `SetSlowWalkBurstSteps` |
| Kiting | `SetKitingPreferredFarthestDistance`, `SetKitingMaximumFarthestDistance`, `SetKitingCloseMonsterDistance`, `SetKitingCloseMonsterCount` |
| Dynamic | `SetStartEndLureActive`, `SetWaypointDynamicLureActive`, `SetUnblocking` |
| Profiles | `GetSettings`, `AddSetting`, `UpdateSetting`, `RemoveSetting`, `ClearSettings` |

`Cavebot.Lure.SetOption(option)` values: **0** = Start/End, **1** = Dynamic, **2** = Kiting.

Kiting preferred, maximum, and close-monster distances accept integers **1–7**. Preferred may not exceed the current maximum, and maximum may not be below preferred — adjust them in a valid order when changing both. Close-monster count accepts **0–200**. These getters/setters edit the same values persisted by Lure Settings.

`UpdateSetting(index, updateData)` updates a 1-based setting through native validation; tables from `GetSettings()` remain detached copies.
