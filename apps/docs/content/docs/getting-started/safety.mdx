## Hard rules

These rules are non-negotiable for generated and hand-written scripts:

1. **Documented APIs only** — never invent a plausible function name; treat an absent function as unavailable.
2. **PascalCase modules only** — do not generate `self.*`, `map.*`, `CaveBot`, `_G.position`, or old `engine.ammoRefill.*` paths.
3. **No busy loops** — repeating work must use `Module.Every`, `Events.Schedule`, or a loop that calls `wait(ms)`.
4. **No `os.execute` / `os.getenv` / `os.tmpname`** — `os.exit()` is reserved for an explicit emergency full-client shutdown policy. It audit-logs and immediately terminates the client without a logout prompt or normal cleanup.
5. **No Objects Dumper** — never expose, query, or toggle it through `Features` / `Engine.Features`.
6. **Validate input** — treat game-derived objects, capabilities, and snapshots as potentially `nil` or stale.
7. **Narrow `pcall` only** — catch only operations with a defined local recovery path. Let unexpected module/event errors reach the runtime policy.
8. **Engine getters are snapshots** — mutating a returned table does nothing; use the matching validated setter.
9. **Idempotent feature changes** — prefer `SetActive` / `Enable` / `Disable` over blind toggles.
10. **Monotonic time** — use `Time.MonotonicMs()` for elapsed time. Never use `os.clock()` for wall-time timeouts.
11. **Event/hook critical path** — every callback registered through `Events`, `Hotkeys`, `Cavebot`/`Walker`, shared-storage `OnChanged`, event proxies, HUD click/drag, or similar APIs must be constant-time and non-yielding. Capture only minimal scalar data into a coalesced slot or hard-bounded queue, then return. See [Events & HUD](/docs/guides/events-hud#event-callback-critical-path).
12. **Restore intentional config** — if the script changes persistent bot configuration, state whether it should remain and restore it in `terminate()` when appropriate.

## Pre-flight checklist

Before deploying a script, verify:

- [ ] All loops yield with `wait`, a module, or a scheduled callback
- [ ] Table access checks nil/type when live game or feature data can be absent
- [ ] Only documented PascalCase APIs and named enum constants are used
- [ ] Feature operations avoid reserved/internal features and use idempotent Set/Enable/Disable
- [ ] Alt is not used for registered callback hotkeys; it is allowed only for `Hotkeys.SendCombo`
- [ ] Position/creature access handles invalid, despawned, or cross-floor objects
- [ ] IDs, indexes, percentages, delays, and ranges are validated before mutation
- [ ] Repeating modules are not hidden inside a blanket `pcall`
- [ ] Event/hook callbacks are constant-time and non-yielding (no `wait`, network, storage/files, profile ops, large JSON, scans, pathfinding, retry loops, or per-event scheduling); they only feed one stable worker via a coalesced slot or hard-bounded queue
- [ ] Named table fields match exact contracts (no guessed aliases like `item.id`)
- [ ] Detached getter snapshots are never edited as live settings
- [ ] Every accepted Walker defer token is completed or intentionally allowed to time out
- [ ] `terminate()` is synchronous, non-yielding, and fast
- [ ] Stable IDs/names are used for modules, events, hotkeys, HUD elements, and storage namespaces
- [ ] Tests print explicit PASS and FAIL results so UI output and per-script logs are useful

## Deprecated patterns

| Do not use | Use instead |
| --- | --- |
| `self.GetHealth()` | `Self.GetHealth()` |
| `map.FindPath(...)` | `Map.FindPath(...)` |
| `CaveBot.Resume()` | `Cavebot.Walker.Resume()` |
| Raw creature globals | `Creature`, `Creatures` modules |
| Legacy `Features` / `Inventory` for new work | Prefer `Engine.Features`, `Engine.Equipment` |
| Blanket `pcall` around `Module.Every` | Narrow catch, or let runtime isolate the module |
| `os.clock()` for timeouts | `Time.MonotonicMs()` |
| Undocumented low-level globals | Documented core wrappers |
| `item.id` / `item.slot` / `container.index` | Exact contract fields (`itemId`, `slotIndex`, …) — see [Table Contracts](/docs/guides/table-contracts) |
| `wait` / HTTP / storage inside an event callback | Coalesce into a slot; drain from `Module.Every` |

## Error handling pattern

```lua
local SCRIPT_ID = "my_script"

local function log(msg)
    print("[" .. SCRIPT_ID .. "] " .. tostring(msg))
end

-- Use pcall only around a known recoverable operation.
local function try_recoverable(fn, context)
    local ok, err = pcall(fn)
    if not ok then
        log("recoverable failure in " .. tostring(context) .. ": " .. tostring(err))
        return false
    end
    return true
end
```

Leave unexpected repeating-module failures uncaught so the runtime can log and isolate the broken module.

## LLM generation rules

When using AI to generate scripts, instruct the model to:

1. Use only exact APIs and enum names from this documentation and the API Reference; never invent a getter, action, or generic update table
2. Prefer canonical core wrappers and `Engine.*` over compatibility globals
3. For every named input, result, or callback record, use [Table Contracts](/docs/guides/table-contracts) / typed API signatures and copy case-sensitive fields exactly — never guess aliases such as `item.id`, `item.slot`, or `container.index`
4. Include argument validation and nil/type checks
5. Use Alt only with `Hotkeys.SendCombo`, never with callback registration
6. Never touch Objects Dumper or other reserved/internal features
7. Use `Module.Every` for repeating work; `Module.After` / `Events.Schedule` for one-shots; all loops must yield
8. Make every event/hook callback constant-time and non-yielding — copy minimal scalars into a coalesced slot or hard-bounded queue for one pre-existing `Module.Every` worker; never wait, do network/storage/file work, scan, pathfind, recursively traverse, or schedule one task per event
9. Do not blanket-`pcall` repeating modules
10. Treat getter tables as snapshots; mutate via explicit setters
11. Use `Time.MonotonicMs()` and `Storage` for timing and persistence
12. Put yieldable setup in `init()` and only fast cleanup in `terminate()`
13. Use stable owner-scoped names and emit explicit PASS/FAIL lines in diagnostic scripts
14. Return a complete runnable `.lua` file without TODO placeholders

## LLM API-selection workflow

For each requested behavior:

1. Find the canonical signature in the [API Reference](/docs/api-reference) and named constants in [Constants](/docs/guides/constants)
2. Resolve every named record under [Table Contracts](/docs/guides/table-contracts) before reading or constructing it; copy field names exactly
3. Prefer the highest-level matching wrapper (`Cavebot`, `Hotkeys`, `Cooldowns`, `Spells`, `Sound`, `Storage`, or a HUD class)
4. Use `Engine.<Feature>` only for explicit feature configuration or actions; call a setter rather than editing a getter snapshot
5. Choose `init`, `Module.Every`, `Module.After` / `Events.Schedule`, or an event proxy based on whether the work is immediate, repeating, one-shot, or event-driven
6. Add capability checks for architecture/client-version-specific functions and nil checks for unavailable game state
7. Identify owner-scoped resources and any shared/live setting that must be restored in `terminate()`
8. Keep errors observable, event callbacks on the critical path, and validation/test output stating PASS or FAIL explicitly

Example prompt:

> Generate a production-safe ValidusBot Lua script using only exact APIs from the attached documentation and its API appendix. Goal: [describe goal]. Resolve every named table record and copy its case-sensitive fields exactly. Prefer canonical high-level wrappers, validate live values, and use managed yielding/scheduling. Every event/hook callback must be constant-time and non-yielding: never call Synchronize/main-thread helpers, lock, wait, perform network/storage work, or start one deferred task per event. Let unexpected module errors reach the runtime. Use Alt only for synthetic SendCombo calls. Return one complete `.lua` file with explicit diagnostic logging and no invented APIs.
